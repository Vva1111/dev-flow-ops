# ROADMAP — DevFlowOps 단계별 구현 계획

> 초기 계획은 약 6~8주 이상을 가정했으며, 관리 화면 확장으로 추가 단계가 필요하다. 아래 주차는 **우선순위 제안**. 일정은 확약이 아니다. 핵심은 실행 가능한 수직 슬라이스와 측정 가능한 결과다.

이 문서는 구현 순서와 완료 기준을 관리하며 진행 상태를 별도로 기록하지 않는다. 현재 구현·미구현 사항은 [개발 진행 현황](DEVELOPMENT_STATUS.md), 실행한 검사는 [검증 기록](DEVELOPMENT_GUIDE.md#6-현재-검증-상태)을 따른다. 자산·예산·저축 목표 전체의 완성을 플랫폼 자동화의 선행 조건으로 두지 않는다.

작업 선택과 우선순위 조정은 [개발 목표 유지 기준](PROJECT_CONTEXT.md#개발-목표-유지-기준), 전체 파이프라인과 구성 요소의 책임은 [아키텍처](ARCHITECTURE.md#1-시스템-개요)를 따른다. 아래 Finance 도메인 확장 항목의 배치가 공통 테스트·CI/CD·배포·QA 연결보다 우선한다는 뜻은 아니다.

## 현재 1차 구현 목표 — 수입·지출 기록·DB 저장·API 문서

- Finance 서버를 실행 가능한 워크스페이스 패키지로 구성하고 선택한 DB 연동을 확인한다.
- 수입·지출 저장 스키마와 마이그레이션을 구성한다.
- 수입·지출 등록·목록 조회·수정·삭제 API를 구현한다.
- Zod 기반 요청·응답 스키마와 라우트 정의에서 OpenAPI 명세를 생성하고 Swagger UI로 제공한다.
- 화면의 입력·목록·수정·삭제 동작을 API와 연결한다.
- API에서 필수 입력값과 금액·날짜를 검증하고 공통 오류 응답을 제공한다.
- 화면에서 입력 오류·요청 실패·처리 중 상태를 안내한다.
- 브라우저에서 등록·새로고침·수정·삭제와 오류 복구를 확인한다.

**완료 기준:** 화면에서 등록·수정·삭제한 결과가 DB와 목록에 반영되고, 새로고침과 서버 재시작 후에도 저장된 내역을 조회할 수 있다. `/api/docs`에서 각 API의 요청·응답 형식, 필수값·제약조건, 응답 코드와 예시를 확인하고 요청을 실행할 수 있으며, `/api/openapi.json`에서 생성된 명세를 제공한다.

자산·부채·예산·저축 목표, 집계 고도화, 금융기관 연동과 파일 가져오기는 이번 완료 조건에서 제외한다. 아래 주차별 계획은 전체 확장 계획이며 현재 작업 범위는 이 1차 목표를 우선한다.

## Milestone 0 (1주차부터 병행): 위험 요소 사전 검증

- OCI Always Free A1 생성 가능/요금/가용 리전 확인.
- GitHub Actions → GHCR → ARM64 이미지 배포 가능성 검토.
- 원격 Linux에서 Codex CLI ChatGPT 구독 로그인 및 `codex exec` 비대화형 실행 테스트.
- OCI 계정 인증 정보 보호/토큰 만료/재시작·재로그인 영향 검증.
- 인증이나 OCI 가용성이 막혀도 개발·CI·테스트를 진행할 대안 수립.

**완료 기준:** PoC 결과가 성공/실패/제약으로 명시되어 있고 가정이 아닌 사실로 기록됨.

## Week 1 — 저장소와 개발 기반

- `DevFlowOps` 명칭으로 GitHub 프로젝트 정리.
- pnpm workspace, Turborepo, React TS Vite 앱 초기화.
- Node/pnpm 버전 및 공통 lint/typecheck/build 명령어 정리.
- README, AGENTS.md와 아키텍처 결정 문서 정리.

**완료 기준:** 새 PC에서 의존성을 설치하고 앱을 로컬에서 실행·빌드할 수 있다. 설정 파일의 존재만으로 새 PC 실행·빌드 검증을 대신하지 않는다.

## Week 2 — Finance App API 및 도메인

- API 프레임워크 결정: Hono.
- ORM 결정: Drizzle ORM.
- 백엔드 런타임과 SQLite 드라이버 선택: Node.js + `node:sqlite`.
- `apps/finance-server`의 서버 책임에 맞는 폴더 구조 구성.
- Finance 서버 `package.json`·실행·빌드·검사 명령과 상태 확인 API 구성.
- 승인된 Drizzle 고정 버전과 Linux의 node:sqlite DB 연동 확인.
- Windows·ARM64 환경의 DB 연동 검증.
- 수입·지출 SQLite 스키마 및 SQL 마이그레이션 정의.
- Transaction 등록·목록·단건 조회·수정·삭제 API와 입력 검증·Swagger UI.
- Category 관리 API와 집계 함수.
- 월말/연말/CRUD 통계 로직에 대한 테스트.

**완료 기준:** API와 도메인 테스트가 재현 가능하게 실행된다.

## Week 3 — Finance App UI

- 소비·자산·예산·목표를 담은 단일 페이지 목업 대시보드와 최근 내역 종류 필터 초안.
- 브라우저에서 데스크톱·모바일 화면 검토 및 퍼블리싱 보완.
- 조회한 내역으로 현재 월의 수입·지출 합계와 카테고리별 소비 분포 표시.
- 기간 선택과 서버 집계 API 연결.
- Transaction: 등록·수정·삭제 폼과 목록 API 연결, 종류 필터와 날짜순 표시.
- 사용자 지정 정렬과 페이지네이션.
- Category: 생성/수정/거래 연결.
- 자산·부채 현황과 순자산의 실제 데이터 연결.
- 월별·카테고리별 예산과 저축 목표의 실제 기능 구현.
- 필요한 공용 UI 또는 도메인 유틸만 패키지로 분리.

**완료 기준:** 핵심 사용자 흐름이 로컬 환경에서 작동한다. 이때부터 구현 증거를 공개하고 구직 활동을 병행할 수 있다.

## Week 4 — 결정론적 테스트와 PR CI

- Vitest, Playwright 시나리오 작성.
- 테스트용 SQLite DB/시드 데이터 분리.
- GitHub Actions에서 PR lint/typecheck/unit/E2E/build 검증.
- Turborepo 의존성/변경 영향 실행 및 캐시 효과를 측정할 기초 수치 기록.

**완료 기준:** 의도적으로 버그를 넣으면 PR CI가 실패한다.

## Week 5 — GHCR / OCI 배포 자동화

- Finance·포털 프론트엔드를 각각의 Nginx 컨테이너로 별도 배포하는 방향 선택.
- 서버 컨테이너 구성, Docker 네트워크 범위·포트·외부 접근 상세 설계.
- production Dockerfile 및 ARM64 빌드.
- GHCR 이미지 발행과 SHA 태깅.
- OCI 호스트 Docker Compose, SQLite 영속 볼륨, HTTPS, 접근 통제 및 백업.
- main 배포 자동화, health check 및 읽기 전용 Smoke Test.

**완료 기준:** 검증된 main 변경이 버전 추적 가능한 배포로 연결된다.

## 추가 단계 A — 플랫폼 관리 화면: 결과 조회

정적 UI 기본 뼈대와 결과 조회 연동을 구분한다. 실제 결과 조회는 QA 결과 계약과 수집이 동작한 뒤 진행한다. AI 분석 완료를 선행 조건으로 두지 않는다.

- `apps/platform-server`의 책임에 맞는 폴더 구조 구성.
- `apps/platform-server`의 패키지·API 구현과 접근 제어·결과 저장 방식 설계.
- Finance App을 첫 관리 대상으로 등록하고 앱별 실행/결과 계약 정의.
- CI/CD·테스트·배포 후 QA 결과를 앱·커밋·환경·배포 버전으로 연결.
- 앱 현황, 실행 이력/상세, 원본 로그·Artifact 링크 제공.
- 수집 실패·미실행·오래된 결과와 AI 분석 상태를 구분하여 표시.

**완료 기준:** Finance App의 동일 커밋에 대한 CI, 배포 버전, 배포 후 QA 결과와 근거를 화면에서 추적할 수 있다. AI가 없어도 조회할 수 있다.

## 추가 단계 B — 제한된 테스트 실행 및 앱 확장

- 허용된 앱·환경·테스트 종류에 대한 수동 실행 요청 API와 UI.
- 인증·권한과 신뢰 가능한 실행 대상, 중복 요청·동시 실행·시간 제한 설계 및 검증.
- Actions/격리 실행기로 요청을 전달하고 대기·실행·완료 및 실패 상태 동기화.
- 앱별 설정과 테스트를 추가하여 공통 자동화를 재사용하는 온보딩 절차 문서화.
- 운영 읽기 전용 Smoke와 격리된 변경 테스트 경계 검증.

**완료 기준:** 화면에서 요청한 테스트를 특정 앱·커밋·환경과 연결해 결과까지 추적한다. 허용되지 않은 요청은 실행하지 않는다. UI 장애가 기존 CI/CD 실행을 막지 않는다. 추가 데모 앱 생성 자체를 완료 조건으로 삼지 않는다.

## 첫 구현에서 하지 않을 것

- 단지 모노레포 시연을 위한 두 번째 앱.
- GitHub/GitLab의 코드 저장·PR 관리 복제, 범용 CI 실행 엔진, 화면에서 임의 명령·운영 배포·롤백 실행.
- 무인 AI 코드 수정/PR merge/운영 자동 롤백.
- 실제 금융 계정 자동 연동이나 복잡한 인증 체계.
- 사용자의 승인 없는 별도 유료 AI API.
- 검증되지 않은 성능/비용/개선 수치의 성과 주장.
