# DevFlowOps 개발 진행 현황

기준일: 2026-11-04. 현재 작업 파일 기준이며, 배포 완료를 의미하지 않는다.

## Finance

### 단계

- 샘플 데이터 기반의 대시보드 퍼블리싱 초안 단계다.
- 화면 구성과 최근 내역 필터만 있으며 실제 데이터 입력·저장은 구현 전이다.

### 목적

- 소비: 수입·지출을 기록하고 어디에 얼마나 쓰는지 파악한다.
- 자산: 계좌·현금·투자·부채를 모아 현재 순자산을 파악한다.
- 계획: 월별·카테고리별 예산과 저축 목표를 관리한다.
- 내역 등록·수정·삭제는 개인의 기록과 오류 정정을 위한 기능이다.
- 내 계좌 간 이체는 수입·지출과 구분한다.
- DevFlowOps의 개발·테스트·배포·품질 검증 흐름을 확인하는 첫 대상이다.

### 구현 사항

- finance-web에 React·TypeScript·Vite 기반 화면을 구성했다.
- 순자산, 월별 수입·지출, 소비 분포, 자산·부채, 예산, 저축 목표를 한 페이지에 배치했다.
- 메뉴는 페이지 내 각 영역으로 이동한다.
- 최근 내역은 전체·지출·수입·이체로 필터링한다.
- 데스크톱·모바일 대응 스타일을 작성했다. 브라우저에서의 실제 화면 검증은 남아 있다.
- finance-server는 폴더 구조와 README만 준비했다.

### 미구현 사항

- 별도 상세 화면과 수입·지출 등록·수정·삭제 기능.
- 실제 자산·부채·예산·저축 목표의 입력과 저장.
- 카테고리 관리, 날짜 필터, 정렬과 페이지네이션.
- 서버 package.json, 실행 코드, API, DB 스키마와 마이그레이션.
- 선택한 Hono·Drizzle·node:sqlite·SQLite의 도입과 연동.
- Vitest·Playwright 테스트와 CI 자동 검증, 컨테이너 배포, 배포 후 QA.

## 포털

### 단계

- 관리 화면의 기본 뼈대와 빈 상태 화면을 구성한 단계다.
- 실제 실행 결과 조회와 테스트 실행 요청은 연결하지 않았다.

### 목적

- 앱별 테스트·CI·배포·배포 후 QA 결과를 한곳에서 추적한다.
- 같은 앱·커밋·환경의 실행 결과와 배포 버전, 원본 로그를 연결한다.
- 결과 조회부터 제공하고, 이후 허용된 대상에 한해 테스트 실행 요청을 지원한다.
- AI 분석은 보조 정보로 제공하며, AI가 없어도 결과를 조회할 수 있어야 한다.

### 구현 사항

- platform-web에 React·TypeScript·Vite 기반 화면을 구성했다.
- Finance를 첫 관리 대상으로 표시한다.
- 테스트·CI·배포·배포 후 QA 단계와 실행 이력의 빈 상태를 표시한다.
- 실제 데이터가 연결되지 않았음을 표시하고 테스트 실행 요청 버튼은 비활성화했다.
- platform-server는 GitHub 연동과 결과 처리를 위한 폴더 구조와 README만 준비했다.

### 미구현 사항

- 서버 package.json, 실행 코드와 API.
- GitHub 인증·연동, 실행 결과 수집과 동기화.
- 앱·커밋·환경·배포 버전별 실제 결과 조회와 원본 로그 연결.
- 인증·권한, 실행 이력 저장 방식과 앱 등록 계약.
- 제한된 테스트 실행 요청, 실행 상태 추적과 동시 실행 제어.
- 공통 QA 실행·수집·보고 도구와 AI 분석 연동.
- 포털 테스트와 CI 자동 검증, 컨테이너 배포.
