# DevFlowOps 개발 진행 현황

기준일: 2026-11-10. 현재 작업 파일 기준이며, 배포 완료를 의미하지 않는다.

## Finance

### 단계

- 화면의 수입·지출 CRUD를 API와 연결하고 DB 저장·API 문서를 구현한 단계다.
- 자산·부채·예산·저축 목표는 샘플이며 브라우저에서 전체 사용자 흐름을 검증하는 작업은 남아 있다.
- 1차 구현 범위는 수입·지출 등록·조회·수정·삭제와 DB 저장, API 스키마 기반 OpenAPI 생성과 Swagger UI 문서 제공으로 확정했다.

### 목적

- 소비: 수입·지출을 기록하고 어디에 얼마나 쓰는지 파악한다.
- 자산: 계좌·현금·투자·부채를 모아 현재 순자산을 파악한다.
- 계획: 월별·카테고리별 예산과 저축 목표를 관리한다.
- 내역 등록·수정·삭제는 개인의 기록과 오류 정정을 위한 기능이다.
- 내 계좌 간 이체는 수입·지출과 구분한다.
- DevFlowOps의 개발·테스트·배포·품질 검증 흐름을 확인하는 첫 대상이다.

### 구현 사항

- finance-web에 React·TypeScript·Vite 기반 화면을 구성했다.
- i18next·react-i18next로 한국어·영어 화면 전환과 언어 선택 저장, 문서 lang 변경을 구성했다. 화면 문구·접근성 라벨·오류 안내와 날짜·KRW 표시를 연결했다. 사용자 입력은 번역하지 않는다.
- 순자산과 월별 수입·지출 카드는 화면 너비 1200px 이상에서 가로로 나란히 배치하고, 그 미만에서는 세로로 배치했다.
- 소비 분포, 자산·부채, 예산, 저축 목표는 박스마다 한 행을 차지하도록 세로로 배치했다.
- 대시보드는 최대 너비를 1080px로 제한하고 가운데 정렬해 좌우 여백을 확보했다.
- 대시보드 본문·금액·표·필터의 글자와 여백을 확대하고, 모바일에서도 읽을 수 있는 크기를 유지했다.
- 하단 footer는 문구를 제거하고 기존 구분선과 여백을 유지했다.
- 메뉴는 페이지 내 각 영역으로 이동한다.
- API에서 전체 기간의 내역을 조회하고 전체·지출·수입으로 필터링한다. 현재 API가 지원하지 않는 이체·계좌 항목은 표시하지 않는다.
- 등록·수정 폼과 삭제 확인을 추가하고 성공 응답을 받은 후 목록을 갱신한다. 실패하면 입력값을 유지한다.
- 조회 중·조회 실패·빈 목록과 저장·삭제 중 상태를 표시하고 조회 재시도와 중복 변경 요청 방지를 구현했다.
- 현재 월의 수입·지출 합계와 카테고리별 소비 분포를 조회한 내역으로 계산하며 자산·예산·목표에는 샘플 표시를 유지한다.
- 데스크톱·모바일 대응 스타일을 작성했다. 브라우저에서의 실제 화면 검증은 남아 있다.
- finance-server를 Hono·Node.js 기반 패키지로 구성하고 개발·빌드·실행·lint·타입 검사 명령과 상태 확인 API를 추가했다.
- Finance 개발 서버의 `/api` 프록시와 화면·서버 동시 실행 명령을 구성했다.
- 수입·지출 등록·목록·단건 조회·수정·삭제 API와 Zod 입력 검증·공통 오류 응답을 구현했다.
- Drizzle `1.0.0-rc.5`와 node:sqlite를 연결하고 SQLite 파일 저장과 서버 시작 시 SQL 마이그레이션을 구성했다.
- 기본 DB는 finance-server의 `data/finance.db`이며 `FINANCE_DB_PATH`로 별도 경로를 지정한다. 샘플 내역은 자동으로 저장하지 않는다.
- 요청·응답 스키마 기반 OpenAPI 명세와 Swagger UI를 `/api/openapi.json`, `/api/docs`에서 제공한다.

### 미구현 사항

- 별도 상세 화면과 서버 집계 API.
- 실제 자산·부채·예산·저축 목표의 입력과 저장.
- 카테고리 관리, 날짜 필터, 정렬과 페이지네이션.
- Vitest·Playwright 테스트와 CI 자동 검증, 컨테이너 배포, 배포 후 QA.

## 포털

### 단계

- 관리 화면의 기본 뼈대와 빈 상태 화면을 구성한 단계다.
- 실제 실행 결과 조회와 테스트 실행 요청은 연결하지 않았다.

### 목적

- 앱별 테스트·CI·배포·배포 후 QA 결과를 한곳에서 추적한다.
- 같은 앱·커밋·환경의 실행 결과와 배포 버전, 원본 로그를 연결한다.
- 결과 조회부터 제공하고, 이후 허용된 대상에 한해 테스트 실행 요청을 지원한다.
- AI 분석은 보조 정보로 제공하며, AI가 없어도 결과를 조회할 수 있어야 한다.

### 구현 사항

- platform-web에 React·TypeScript·Vite 기반 화면을 구성했다.
- i18next·react-i18next로 한국어·영어 화면 전환과 언어 선택 저장, 문서 lang·제목 변경을 구성했다.
- Finance를 첫 관리 대상으로 표시한다.
- 테스트·CI·배포·배포 후 QA 단계와 실행 이력의 빈 상태를 표시한다.
- 실제 데이터가 연결되지 않았음을 표시하고 테스트 실행 요청 버튼은 비활성화했다.
- 하단 footer의 기존 AI 분석 미연결 메시지를 유지했다.
- platform-server는 GitHub 연동과 결과 처리를 위한 폴더 구조와 README만 준비했다.

### 미구현 사항

- 서버 package.json, 실행 코드와 API.
- GitHub 인증·연동, 실행 결과 수집과 동기화.
- 앱·커밋·환경·배포 버전별 실제 결과 조회와 원본 로그 연결.
- 인증·권한, 실행 이력 저장 방식과 앱 등록 계약.
- 제한된 테스트 실행 요청, 실행 상태 추적과 동시 실행 제어.
- 공통 QA 실행·수집·보고 도구와 AI 분석 연동.
- 포털 테스트와 CI 자동 검증, 컨테이너 배포.
